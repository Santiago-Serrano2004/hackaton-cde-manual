**Convenciones comunes (aplican a esta tarea):**

- **Idioma:** código, commits y nombres técnicos en inglés cuando son del framework; **tablas, columnas, rutas de API y textos de interfaz en español** (`03` §6).
- **Backend:** monolito modular en `backend/app/Modules/<Modulo>/` (rutas en `Modules/<Modulo>/routes.php`, *Actions* para casos de uso, *Form Requests* para validar, *API Resources* para JSON, *Policies* para permisos con **denegar por defecto**). - **API:** prefijo `/api/v1`, JSON, `Authorization: Bearer <token>` (Sanctum); paginación `?page=&per_page=` (máximo 50); errores `{ "message": "…", "errors": { "campo": ["…"] } }`; códigos 200/201/204, 401, 403, 404, 409 (conflicto), 422 (validación), 429.

- **Frontend:** `frontend/src/modules/<modulo>/` (rutas en `routes.tsx`), componentes de `frontend/src/components/ui`, estilos con los tokens de `16_sistema_de_diseno.md`, validación con `zod`, datos de servidor con TanStack Query, gráficas con `recharts` cargadas por ruta (`React.lazy`).

- **Commits:** `feat(<modulo>): …` / `fix(...)` / `test:` / `docs:` con `Refs T-xx` en el cuerpo; una tarea = un commit (o una rama `feat/<modulo>-<tarea>`) hacia `develop`; `main` solo por PR con CI verde.

## 4. Contratos

`GET /api/v1/reportes/caracterizacion?sector=&tamano=&formalizacion=&relacion_unab=` → `{"total":497,"por_sector":[{"nombre":"Alimentos","n":50}],"sin_dato":{"sector":317,"tamano":313},"por_tamano":[…],"por_formalizacion":[…],"por_relacion_unab":[…]}`.
`GET /api/v1/reportes/brechas?sector=&tamano=` → `{"n":50,"advertencia":null|"n<5","dimensiones":[{"dimension":"Finanzas","brecha_media":41.2,"empresas_afectadas":22}]}`.
`GET /api/v1/reportes/impacto?desde=&hasta=&formato=json|csv` → KPIs: empresas atendidas, atenciones, proyectos, compromisos cumplidos/vencidos, variación media de madurez (primer vs. último diagnóstico), asistencia a eventos. `formato=csv` devuelve `text/csv; charset=UTF-8` con BOM.

## 5. Reglas de negocio

1. Las cifras vienen de vistas SQL; cada cifra del dashboard coincide con su consulta de control de `08`.
2. Brechas: se toma el **último** diagnóstico de cada empresa; `brecha = 100 − puntaje` por dimensión; se devuelve `n`; si `n < 5` se incluye la advertencia y no se infiere.
3. Caracterización muestra también los `sin_dato` (hace visible el problema de calidad: 36 % con sector, 37 % con tamaño).
4. Exportación CSV con BOM UTF-8 y separador `,`; el PDF sale de la vista imprimible del navegador (no hay dependencia de dompdf aquí).
5. Reporte en ≤ 10 s; caché de KPIs de 5 min.
6. Solo roles `administrador` y `equipo_cde`.

## 6. Casos límite

1. Periodo sin datos → ceros y mensaje «Sin datos en el periodo».
2. `desde > hasta` → 422.
3. Sector inexistente → 422.
4. Empresa sin diagnóstico: no cuenta en brechas pero sí en caracterización.

## 14. R3 (F22, RK-1) · Exportación segura

Al generar el CSV, toda celda de texto que empiece por `=`, `+`, `-` o `@` se antepone con `'` (comilla simple) para evitar la ejecución de fórmulas al abrirlo en Excel. Prueba en `ReporteTest`: una razón social `=1+1` sale como `'=1+1`. Costo: una línea, absorbida por las 0,75 h de la tarea.

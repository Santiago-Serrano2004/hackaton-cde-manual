## 1. Contexto mínimo

Interfaz de calidad de datos (D-03). Responsable: María Paula. Nivel 2 (Should).

Producto: sistema de gestión de información del Centro de Desarrollo Empresarial (CDE) de la UNAB, reto «De datos dispersos a conocimiento que innova» (Hackatón 28–29 oct 2026). Stack fijado: Laravel 13 (PHP 8.3/8.4) + PostgreSQL 18 con `pg_trgm` + Sanctum + spatie/laravel-permission + Pest 4 en `backend/`; React 19.3.1 + Vite 8.3.5 + Tailwind 4.3.3 + TypeScript 5.9.3 en `frontend/` (versiones de `12_verificacion.md` y `15_frontend_skills_y_ui.md`).

**Convenciones comunes (aplican a esta tarea):**

- **Idioma:** código, commits y nombres técnicos en inglés cuando son del framework; **tablas, columnas, rutas de API y textos de interfaz en español** (`03` §6).
- **Backend:** monolito modular en `backend/app/Modules/<Modulo>/` (rutas en `Modules/<Modulo>/routes.php`, *Actions* para casos de uso, *Form Requests* para validar, *API Resources* para JSON, *Policies* para permisos con **denegar por defecto**). Un módulo nunca escribe tablas de otro: se comunica por *Actions* públicas o eventos de dominio (`05` §2).
- **API:** prefijo `/api/v1`, JSON, `Authorization: Bearer <token>` (Sanctum); paginación `?page=&per_page=` (máximo 50); errores `{ "message": "…", "errors": { "campo": ["…"] } }`; códigos 200/201/204, 401, 403, 404, 409 (conflicto), 422 (validación), 429.
- **Datos:** PostgreSQL; todas las tablas con `id`, `created_at`, `updated_at`, `deleted_at` (borrado lógico) salvo las indicadas; FK `ON DELETE RESTRICT`; `empresa_id` NOT NULL en toda entidad que cuelga de una empresa.
- **Auditoría:** toda escritura registra `auditoria` con `Auditor::registrar()`.
- **Frontend:** `frontend/src/modules/<modulo>/` (rutas en `routes.tsx`), componentes de `frontend/src/components/ui`, estilos con los tokens de `16_sistema_de_diseno.md`, validación con `zod`, datos de servidor con TanStack Query, gráficas con `recharts` cargadas por ruta (`React.lazy`).
- **Pruebas:** Pest 4 en `backend/tests/{Feature,Unit}`; Vitest para utilidades y componentes; Playwright para el camino de usuario.
- **Commits:** `feat(<modulo>): …` / `fix(...)` / `test:` / `docs:` con `Refs T-xx` en el cuerpo; una tarea = un commit (o una rama `feat/<modulo>-<tarea>`) hacia `develop`; `main` solo por PR con CI verde.
- **Datos de prueba:** únicamente sintéticos (RNF-14); nunca datos reales.
- **No hacer:** no actualizar dependencias; no añadir paquetes que no estén en `15` §3 sin acuerdo; no tocar módulos ajenos salvo por el contrato indicado.

## 2. Entradas (qué debe existir antes)

Tareas previas: T-18, T-40. Si una dependencia no está lista, **no la reconstruyas**: usa un doble de prueba (*mock*) del contrato indicado en §4 y avisa en el canal del equipo.

## 3. Archivos a crear o tocar

- `frontend/src/modules/calidad/` con `TarjetaCalidad.tsx`, `AnilloCompletitud.tsx`, `ListaPendientes.tsx`

## 4. Contratos

Consume `GET /api/v1/reportes/calidad` (T-18), `GET /api/v1/empresas?incompletas=` y `GET /api/v1/tareas-calidad` (T-26). `AnilloCompletitud` props: `valor: number (0–100)`, `faltantes: string[]`.

## 5. Reglas de negocio

1. Tarjeta global en el panel del día (E1) con cifra, `n` y enlace a la lista de pendientes.
2. Anillo de completitud en la cabecera de la ficha (E3) y en «Mi empresa» (M6); al llegar a 100 % cambia a `--exito` con check.
3. Lista de pendientes filtrable por campo faltante; cada fila abre la ficha en el campo.
4. Al completar una ficha el valor se actualiza sin recargar y, para el emprendedor, aparece el toast «+puntos» (T-43).
5. Texto alternativo del anillo: «Datos completos 82 %».

## 6. Casos límite

1. Sin pendientes: mensaje de logro, no pantalla vacía.
2. Error de red: banda con «Reintentar».

## 7. Pruebas esperadas
